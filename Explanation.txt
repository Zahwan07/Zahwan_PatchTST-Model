================================================================================
  PATCHTST PLANT GROWTH PREDICTION — CODE & METHODOLOGY EXPLANATION
  (For Research Paper / Final College Project)
================================================================================

This document describes the ACTIVE pipeline: Open-Meteo hourly data, six
separate PatchTST models (Multi_Model), and a one-month (720-hour) forecast
written to Main_model/prediction_forecast.csv. A short legacy section at the
end summarizes the older single-model Main_model path if you still need it.

--------------------------------------------------------------------------------
1. PROJECT OVERVIEW
--------------------------------------------------------------------------------

Goal: Predict the next 30 days (720 hourly steps) of environment variables for
hydroponic red leaf lettuce (Lactuca sativa L.) near Bandung, Indonesia, then
optionally turn the forecast into natural-language recommendations via an LLM.

Main outputs (columns in Main_model/prediction_forecast.csv), aligned with
Main_model/config_exp.FEATURES_FORECAST:

  - suhu              = air temperature (deg C)
  - cuaca             = weather class (0 = clear, 1 = cloudy, 2 = rain)
  - humidity          = relative humidity (0-1 scale in data)
  - light_intensity   = shortwave radiation proxy (W/m^2)
  - ph                = substrate pH (slow-varying series)
  - precipitation     = hourly precipitation (mm)

There is no soil-moisture ("kelembapan") column in the current hydroponic
pipeline; humidity is air relative humidity from Open-Meteo.

Horizons (defaults shared via Main_model/config_exp.py and
Multi_Model/multi_config.py): INPUT_LEN = 168 (one week of past hours),
PRED_LEN = 720 (30 days of future hours).


--------------------------------------------------------------------------------
2. WHERE IS PATCHTST AND HOW DOES IT WORK?
--------------------------------------------------------------------------------

File: model/patchtst_official.py (wraps PatchTST-main/PatchTST_supervised)

The project uses the official PatchTST architecture from "A Time Series is
Worth 64 Words" (Nie et al.):

  - Input per model: (batch, 168, D_l) where D_l is the number of features for
    that label (different for each of the six models). Values come from
    EnvironmentPreprocessor (StandardScaler on continuous columns only for
    these feature lists; cuaca is NOT one-hot inside the Multi_Model subsets).

  - Patching: 168 hours are turned into patch tokens (defaults: patch_len=16,
    stride=8 in Multi_Model/multi_config.py). Each patch is embedded to
    d_model=128. The Transformer sees a shorter patch sequence than 168 raw steps.

  - RevIN: Reversible Instance Normalization per channel where enabled in the
    official config.

  - Backbone: Transformer encoder over patch tokens (3 layers, 16 heads,
    d_model=128 in the current training scripts).

  - Regression head (five models): The official PatchTST head predicts all D_l
    channels for each of the next PRED_LEN hours; training stresses the target
    channel (index 0 in FEATURES_BY_LABEL[label]) via a channel-weighted MSE.

  - Cuaca head (one model): Multi_Model/train_multi.py defines CuacaPatchTST:
    same PatchTST_Official backbone, then a linear layer mapping per-timestep
    features to 3 logits (clear / cloudy / rain) for each of the PRED_LEN steps.

Detailed hyperparameters may drift; see Multi_Model/multi_config.py and
Multi_Model/train_multi.py for the exact numbers used in code.


--------------------------------------------------------------------------------
3. CURRENT PIPELINE — PRIMARY (MULTI_MODEL), FILE BY FILE
--------------------------------------------------------------------------------

--- fetch_openmeteo_historical.py ---

  Purpose: Build the single CSV used for training and inference.

  - Fetches hourly archive weather for Bandung (latitude -6.8783, longitude
    107.6219), in yearly chunks, via Open-Meteo.
  - API-style columns include temperature, humidity, dewpoint, pressure,
    cloud cover, shortwave radiation, wind, precipitation, weather_code.
  - Writes data/historical_environment.csv with derived fields (e.g. cyclical
    time, wind sin/cos, temp lags) and lettuce-oriented series (humidity 0-1,
    light_intensity, ph, cuaca from precipitation thresholds).
  - Cuaca in the CSV uses the same precipitation thresholds as the training
    labels for the classifier: see precip_to_cuaca in Multi_Model/datasets_multi.py
    (rain if precip > 0.5, cloudy if > 0.1, else clear).


--- Main_model/config_exp.py ---

  Purpose: Global defaults for feature lists and horizons.

  - ALL_FEATURES: numeric columns in historical_environment.csv (excluding time).
  - FEATURES_FORECAST: the six columns written to prediction_forecast.csv.
  - INPUT_LEN = 168, PRED_LEN = 720.
  - Multi_Model/multi_config imports INPUT_LEN and PRED_LEN from here so one
    place defines the horizon.


--- Multi_Model/multi_config.py ---

  Purpose: Per-label feature subsets and artifact paths.

  - REGRESSION_LABELS: suhu, humidity, light_intensity, ph, precipitation.
  - FEATURES_BY_LABEL: each list starts with the regression target for that
    model, followed by context variables (cloud, time cycles, lags, etc.).
  - FEATURES_BY_LABEL["cuaca"]: inputs for the weather classifier (no cuaca in X;
    labels are derived from precipitation in datasets_multi).
  - artifacts_dir / artifacts_for_label: models and preprocessors live under
    Main_model/Multi_Model/artifacts/ as patchtst_<label>.pth and
    preprocessor_<label>.joblib (cuaca uses patchtst_cuaca.pth).


--- Multi_Model/datasets_multi.py ---

  Purpose: Build numpy window tensors for training.

  - load_historical_df(): reads and time-sorts data/historical_environment.csv.
  - create_windows_xy(): sliding windows X[i] = data[i : i+INPUT_LEN],
    Y[i] = data[i+INPUT_LEN : i+INPUT_LEN+PRED_LEN], only where full future exists.
  - build_regression_dataset(label): scales FEATURES_BY_LABEL[label], returns
    X (N, 168, D), Y (N, 720, D), preprocessor, feature list.
  - build_cuaca_dataset(): scales cuaca input features; Y is shape (N, 720) of
    class indices from precip_to_cuaca applied to raw precipitation.


--- Multi_Model/train_multi.py ---

  Purpose: Train all six models and save artifacts.

  - For each regression label: build dataset, 80/20 train/val split, Adam,
    channel-weighted MSE on the target channel, early stopping on validation loss,
    save state_dict + preprocessor to Main_model/Multi_Model/artifacts/.
  - Cuaca: CuacaPatchTST with cross-entropy on flattened (time, class) logits;
    class weights from inverse frequency on training labels to mitigate imbalance.
  - Run from repo root: python Multi_Model/train_multi.py
  - To retrain only cuaca after changing classifier logic or data:
    python Multi_Model/train_multi.py --cuaca-only


--- Multi_Model/predict_multi.py ---

  Purpose: Load all six artifacts and write Main_model/prediction_forecast.csv.

  - For each regression label: last 168 rows of CSV -> label preprocessor ->
    PatchTST_Official -> inverse transform -> one column of length 720.
  - Cuaca: last 168 rows with cuaca preprocessor -> CuacaPatchTST -> argmax over
    three classes per hour.
  - Exported cuaca column: element-wise max of (classifier argmax, class derived
    from the predicted precipitation series using the SAME thresholds as
    precip_to_cuaca). Reason: supervised windows require INPUT_LEN + PRED_LEN rows
    of history+future inside the CSV, so the exact "last 168 hours" input used at
    deployment is not present as labeled training input when PRED_LEN > 0; the
    regression head still emits a full precip trace, and the max rule keeps
    exported weather classes consistent with that trace for the thesis/ops CSV.


--- Main_model/eval_exp.py ---

  Purpose: Offline evaluation on Multi_Model artifacts (regression metrics on
  scaled target channel; mean per-step accuracy for cuaca classifier).

  - Run: python Main_model/eval_exp.py (from repo root).


--- utils.py ---

  Purpose: compute_metrics (MAE, RMSE, MAPE, etc.) used in train_multi validation
  printing for regression heads.


--- Main_model/preprocessor.py (EnvironmentPreprocessor) ---

  Purpose: StandardScaler on the configured feature columns; optional legacy
  one-hot for cuaca only when "cuaca" appears in the fitted feature list tied to
  ALL_FEATURES. Multi_Model per-label lists omit cuaca from X for the cuaca model,
  so those preprocessors are continuous-only for their feature vectors.


--- llm_recommendations.py ---

  Purpose: Optional natural-language recommendations from a numeric forecast;
  can consume rows/columns from prediction_forecast.csv if adapted to the six
  output columns.


--------------------------------------------------------------------------------
4. END-TO-END DATA FLOW (PRIMARY)
--------------------------------------------------------------------------------

  (1) Data
      python fetch_openmeteo_historical.py
        -> data/historical_environment.csv

  (2) Training (GPU recommended; long run)
      python Multi_Model/train_multi.py
        -> Main_model/Multi_Model/artifacts/patchtst_*.pth and preprocessor_*.joblib

  (3) Prediction
      python Multi_Model/predict_multi.py
        -> Main_model/prediction_forecast.csv (720 rows, columns in FEATURES_FORECAST)

  (4) Optional evaluation
      python Main_model/eval_exp.py


--------------------------------------------------------------------------------
5. KEY EQUATIONS (FOR PAPER)
--------------------------------------------------------------------------------

  - For regression label l with D_l input channels:
      X_l in R^{168 x D_l},   Y_l in R^{720 x D_l}  (scaled space).
      PatchTST maps X_l to Y_hat_l with the same tail shape; loss stresses channel 0.

  - For cuaca classifier:
      X_c in R^{168 x D_c}; logits Z in R^{720 x 3}; class y_hat_t = argmax Z_t.
      Training minimizes weighted cross-entropy over all (t, class) pairs.

  - Precipitation-to-class mapping (labels and fusion):
      c(p) = 2 if p > 0.5, else 1 if p > 0.1, else 0.

  - Exported forecast weather class:
      cuaca_export_t = max( y_hat_t, c( precip_forecast_t ) ) with max in {0,1,2}.

6. LEGACY PIPELINE (MAIN_MODEL — SINGLE PATCHTST)
--------------------------------------------------------------------------------

These files remain in the repository for an earlier experiment: one PatchTST over
a single encoded tensor (historically 19 channels with cuaca one-hot) and a
different forecast length in older docs. They are NOT what predict_multi.py uses.

  - Main_model/train2.py          — trains one PatchTST_Official, saves e.g.
                                    Main_model/patchtst_model_exp.pth
  - Main_model/predict_exp.py     — single-model forecast path
  - Main_model/preprocess.py      — windowing helper for that path
  - Main_model/preprocessor.py    — shared class; legacy mode if cuaca in ALL_FEATURES

Use Multi_Model for the six-model hydroponic pipeline and the current
FEATURES_FORECAST layout.


--------------------------------------------------------------------------------
7. WHY PATCHTST INSTEAD OF GRU/LSTM?
--------------------------------------------------------------------------------

  - Parallelism: Transformers process the patched sequence in parallel; RNNs are
    inherently more sequential.
  - Long-range dependencies: Self-attention connects distant patches directly.
  - PatchTST is a strong baseline for long-horizon forecasting; this project uses
    the official implementation with patching and RevIN.
