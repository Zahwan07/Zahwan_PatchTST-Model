================================================================================
  PATCHTST PLANT GROWTH PREDICTION — CODE & METHODOLOGY EXPLANATION
  (For Research Paper / Final College Project)
================================================================================

This document explains the current pipeline: how data is fetched, how
PatchTST is trained, and how predictions are produced. The active pipeline
uses Open-Meteo historical data and the Main_model (hourly, 2-week forecast).

--------------------------------------------------------------------------------
1. PROJECT OVERVIEW
--------------------------------------------------------------------------------

Goal: Predict the next 2 weeks of environment conditions (temperature, weather,
soil moisture, pH) for red leaf lettuce (Lactuca sativa L.) in Bandung, then
optionally turn the forecast into natural-language recommendations via an LLM.

Main outputs (4 features in prediction_forecast.csv):
  - suhu       = temperature (°C)
  - cuaca      = weather (0=clear, 1=cloudy, 2=rain)
  - kelembapan = soil moisture (0–1)
  - ph         = soil/substrate pH (optimal 6.0–7.0 for lettuce)

The model uses additional inputs (dewpoint, pressure, cloud cover, solar
radiation, wind, cyclical time, temperature lags) to improve accuracy. Only
suhu, cuaca, kelembapan, ph are written to the forecast CSV for lettuce use.


--------------------------------------------------------------------------------
2. WHERE IS PATCHTST AND HOW DOES IT WORK?
--------------------------------------------------------------------------------

File: model/patchtst_official.py (wraps PatchTST-main)

The project uses the official PatchTST architecture from "A Time Series is
Worth 64 Words" (Nie et al.):

  - Input: (batch, 168, n_features). 168 hours (1 week) of past data; n_features
    is 19 after encoding (16 continuous scaled + 3 one-hot for cuaca).

  - Patching: The 168 timesteps are split into patches (patch_len=16, stride=8).
    Each patch is projected to d_model=128. The sequence length seen by the
    Transformer is reduced (e.g. ~21 patch tokens instead of 168 raw steps).

  - RevIN: Reversible Instance Normalization is applied per channel before and
    after the backbone so the model sees normalized inputs and outputs are
    denormalized.

  - Backbone: Transformer encoder over the patch tokens (3 layers, 16 heads,
    d_model=128). Self-attention captures long-range dependencies.

  - Head: Linear layer maps the patch representations to pred_len × n_features.
    With PRED_LEN=336, the model outputs 336 future hours (2 weeks) for all
    features.

  - Output: (batch, 336, 19) in encoded space; after inverse transform, the
    forecast CSV saves only [suhu, cuaca, kelembapan, ph] (4 columns).


--------------------------------------------------------------------------------
3. CURRENT PIPELINE — FILE BY FILE
--------------------------------------------------------------------------------

--- fetch_openmeteo_historical.py ---

  Purpose: Build the single source of training and prediction input data.

  - Fetches hourly historical weather from Open-Meteo Archive API for Bandung
    (latitude -6.8783, longitude 107.6219), in yearly chunks.
  - API variables: temperature_2m, relative_humidity_2m, dewpoint_2m,
    surface_pressure, cloud_cover, shortwave_radiation, wind_speed_10m,
    wind_direction_10m, precipitation.
  - Derived: cuaca (0/1/2 from precipitation), kelembapan (synthetic soil
    moisture from precip + humidity), ph (slow drift 6–7), suhu (= temperature_2m).
  - Cyclical time: hour_sin, hour_cos, doy_sin, doy_cos from timestamps.
  - Wind: wind_dir_sin, wind_dir_cos from wind_direction_10m.
  - Lags: temp_lag_24, temp_lag_168 (temperature 24 h and 168 h ago).
  - Writes data/historical_environment.csv (time + 17 feature columns). Run
    this first when refreshing data; then train and predict use this file.


--- Main_model/config_exp.py ---

  Purpose: Configuration for the Main_model pipeline.

  - ALL_FEATURES: List of 17 column names (suhu, cuaca, kelembapan, ph, plus
    dewpoint, pressure, cloud_cover, shortwave_radiation, wind, cyclical time,
    temp lags).
  - FEATURES_FORECAST: [suhu, cuaca, kelembapan, ph] — columns written to
    prediction_forecast.csv.
  - INPUT_LEN = 168 (1 week of hours), PRED_LEN = 336 (2 weeks).


--- Main_model/preprocessor.py ---

  Purpose: Encode features for the model; inverse transform for human-readable output.

  - Cuaca is treated as categorical: one-hot encoded (3 columns for 0/1/2).
  - All other numeric columns are scaled with StandardScaler.
  - transform(df): Returns array of shape (n, 19) — 16 continuous scaled + 3 one-hot.
  - inverse_transform(X): Converts model output (19 cols) back to 17 original
    columns (continuous unscaled, cuaca from argmax of one-hot).
  - n_features_in_: 19 (used as model input_dim). Saved as preprocessor_exp.joblib.


--- Main_model/preprocess.py ---

  Purpose: Load CSV and build (X, Y) windows for training.

  - prepare_data(): Reads data/historical_environment.csv, fits and applies
    EnvironmentPreprocessor, returns (data_scaled, preprocessor).
  - create_dataset(data, input_len, pred_len): Sliding windows. X[i] = data[i : i+168],
    Y[i] = data[i+168 : i+168+336]. Shapes (n_samples, 168, 19) and (n_samples, 336, 19).


--- Main_model/train2.py ---

  Purpose: Train the official PatchTST and save the best checkpoint and preprocessor.

  - Loads data via prepare_data() and create_dataset(); 80% train / 20% validation.
  - Model: PatchTST_Official(input_dim=19, input_len=168, pred_len=336, patch_len=16,
    stride=8, d_model=128, n_heads=16, num_layers=3, revin=True).
  - Loss: MSE. Optimizer: Adam (lr=0.001, weight_decay=1e-4).
  - Mini-batch training (batch size 256 on GPU, 64 on CPU) to avoid OOM.
  - Every 10 epochs: validation loss and metrics (MAE, MSE, RMSE, MAPE). MAPE is
    computed only on continuous columns [0,1,2] (suhu, kelembapan, ph) to avoid
    distortion from one-hot cuaca.
  - Early stopping: if validation loss does not improve for PATIENCE (50) epochs,
    training stops; best state is restored.
  - Saves: Main_model/patchtst_model_exp.pth, Main_model/preprocessor_exp.joblib.


--- Main_model/predict_exp.py ---

  Purpose: Produce the 2-week forecast and write prediction_forecast.csv.

  - Loads preprocessor (preprocessor_exp.joblib) and model (patchtst_model_exp.pth).
  - Reads data/historical_environment.csv, takes last 168 rows, transforms with
    preprocessor.transform() → (168, 19).
  - Forward: model(input_tensor) → (1, 336, 19). Inverse transform → (336, 17).
  - Selects FEATURES_FORECAST columns (suhu, cuaca, kelembapan, ph), adds
    timestamps (first prediction = 1 hour after last input row).
  - Writes Main_model/prediction_forecast.csv and prints a sample (first days,
    last days). Optional: use llm_recommendations to send forecast text to an LLM.


--- utils.py ---

  Purpose: Evaluation metrics used in Main_model/train2.py.

  - mae, mse, rmse (root mean squared error = sqrt(mse)), smape (symmetric MAPE).
  - compute_metrics(pred, target, continuous_cols=None): Returns MAE, MSE, RMSE,
    MAPE. If continuous_cols is provided (e.g. [0,1,2]), MAPE is computed only
    on those columns (for stability when cuaca is one-hot).


--- llm_recommendations.py ---

  Purpose: Turn a numeric forecast into text and get natural-language recommendations.

  - forecast_to_text(forecast_7d): Formats forecast dicts/array as text.
  - get_llm_recommendations(forecast_text, crop, location): Sends prompt to LLM API.
  - get_recommendations_from_forecast(forecast_7d, ...): Convenience wrapper.
  - Can be used with the output of predict_exp (e.g. pass the 336-hour forecast
    summarized by day or a subset) to get lettuce care recommendations.


--------------------------------------------------------------------------------
4. END-TO-END DATA FLOW (CURRENT)
--------------------------------------------------------------------------------

  (1) Data
      python fetch_openmeteo_historical.py
        → data/historical_environment.csv (time + 17 features, hourly, 5+ years)

  (2) Training
      python Main_model/train2.py
        → Main_model/preprocess.prepare_data() loads CSV, preprocessor fits/transforms
        → create_dataset() → (X, Y) with shapes (n, 168, 19), (n, 336, 19)
        → Train PatchTST_Official, early stopping, save best model + preprocessor
        → Main_model/patchtst_model_exp.pth, Main_model/preprocessor_exp.joblib

  (3) Prediction
      python Main_model/predict_exp.py
        → Load preprocessor and model
        → Last 168 hours from historical_environment.csv → transform → (1, 168, 19)
        → model(input) → (1, 336, 19) → inverse_transform → select suhu, cuaca,
          kelembapan, ph → Main_model/prediction_forecast.csv (336 rows, 2 weeks)

--------------------------------------------------------------------------------
6. WHY PATCHTST INSTEAD OF GRU/LSTM?
--------------------------------------------------------------------------------

  - Parallelism: Transformers process the full input (168 hours as patches) in
    parallel; RNNs are sequential.
  - Long-range dependencies: Self-attention lets any patch attend to any other;
    in RNNs, information from early steps can fade.
  - PatchTST in the literature achieves strong long-horizon forecasting; this
    project uses the official implementation (PatchTST-main) with patching,
    RevIN, and 2-week prediction.


--------------------------------------------------------------------------------
7. KEY EQUATIONS (FOR PAPER)
--------------------------------------------------------------------------------

  - Input:  X ∈ R^{168×19}  (168 hours, 19 encoded features)
  - Patching: 168 → ~21 patch tokens, each patch projected to d_model.
  - RevIN: normalize → backbone → denormalize.
  - Output:  Y_pred ∈ R^{336×19}  (336 hours, 19 features); forecast CSV uses
    the 4 columns [suhu, cuaca, kelembapan, ph].
  - Loss: L = MSE(Y_pred, Y_true). Metrics: MAE, MSE, RMSE, MAPE (on continuous
    targets for MAPE).
